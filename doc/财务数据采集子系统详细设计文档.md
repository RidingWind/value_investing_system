## 1. 模块概述

### 1.1 设计理念

本子系统采用**以指标为核心**的元数据驱动架构，实现财务数据的完全动态采集。

- **API**：财务数据源的接口，定义输入参数和输出列。API 不直接关联报表，而是通过指标公式间接被引用。
- **指标**：全局标准字段，如 `revenue`、`roe`。每个指标包含完整的计算公式（Python 表达式），公式中可引用任意 API 的输出列名、系统内置变量和 Python 内置函数。
- **报表分组**：报表降级为一个**逻辑分组标签**，仅用于前端展示分类（利润表、资产负债表等），不影响采集逻辑。
- **依赖管理**：系统在保存指标时自动解析公式，提取引用的 API 函数和列名，存入 `indicator_api_dep` 表，实现血缘分析和变更通知。

### 1.2 核心优势

- **极致灵活**：指标可跨报表复用，支持跨 API 复合计算。
- **自动溯源**：公式解析引擎自动建立指标与 API 的依赖关系。
- **安全沙箱**：公式执行时使用受限 `eval`，仅允许访问 `row` 变量、部分内置函数，杜绝恶意代码。
- **热配置**：增删改指标或 API 无需重启服务，Web 界面实时生效。
- **多源切换**：修改指标的公式即可变更数据来源，无需改动报表结构。

## 2. 核心实体关系模型

```
┌────────────────────┐
│     api_def        │
│  - id              │
│  - function_name   │
│  - output_columns  │
│  - input_params    │
└────────┬───────────┘
         │
         │ 1:N  (一个API被多个指标依赖)
         ▼
┌──────────────────────────┐
│   indicator_api_dep      │  ← 自动维护的依赖关系表
│  - indicator_id          │
│  - api_id                │
│  - column_name           │
│  - formula               │
└──────────┬───────────────┘
           │
           │ N:1  (多个依赖记录属于同一个指标)
           ▼
┌────────────────────┐
│  indicator_def     │
│  - id              │
│  - standard_field  │
│  - formula         │
│  - formula_version │
│  - report_group    │ (可选分组字符串)
└────────────────────┘
```

**关系说明**：

- **指标** 是核心，包含计算公式。
- **API** 不直接关联报表，而是通过指标公式被间接引用。
- **`indicator_api_dep`** 表由系统在保存指标时自动生成，记录每个指标依赖的 API 函数名和列名，用于血缘分析、变更通知和依赖图展示。
- **报表分组** 仅作为指标的 `report_group` 属性，用于前端分类展示，不影响逻辑。

## 3. 数据库设计

### 3.1 表结构

#### 3.1.1 `api_def` — API 定义表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer, PK | 主键 |
| source | String(20) | 数据源标识，默认 `akshare` |
| function_name | String(100) | AKShare 函数名 |
| chinese_name | String(200) | 中文描述 |
| description | Text | 详细说明 |
| input_params | JSON | 输入参数模板，支持占位符 `{em_symbol}`, `{start_year}` 等 |
| output_columns | JSON | 输出列名列表（字符串数组） |
| date_column | String(50) | 日期列名 |
| filter_condition | String(200) | 可选筛选表达式 |
| created_at | DateTime | 创建时间 |

#### 3.1.2 `indicator_def` — 指标定义表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer, PK | 主键 |
| standard_field | String(50) | 标准字段名，如 `revenue`, `roe` |
| chinese_name | String(100) | 中文名称 |
| data_type | String(20) | 数据类型，默认 `float` |
| unit | String(20) | 单位（`元`、`%`、`倍`） |
| formula | Text | 计算公式（Python 表达式） |
| formula_version | Integer | 公式版本号（自动递增） |
| report_group | String(20) | 报表分组标签：`income`/`balance`/`cashflow`/`indicator` |
| description | Text | 说明 |
| created_at | DateTime | 创建时间 |
| updated_at | DateTime | 最后修改时间 |

#### 3.1.3 `indicator_api_dep` — 指标-API 依赖表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer, PK | 主键 |
| indicator_id | Integer, FK | 关联 `indicator_def.id` |
| api_id | Integer, FK | 关联 `api_def.id` |
| column_name | String(100) | 引用的 API 输出列名 |
| extracted_at | DateTime | 提取时间 |

### 3.2 索引与约束

- `api_def`：`UNIQUE(source, function_name)`
- `indicator_def`：`UNIQUE(standard_field)`
- `indicator_api_dep`：`UNIQUE(indicator_id, api_id, column_name)`
- 为 `report_group` 字段添加索引，加速前端分组查询。

## 4. 核心类设计

### 4.1 动态适配器 (`DynamicFinancialAdapter`)

适配器不再绑定特定报表，只负责根据指标公式计算单一指标的值，或根据一组指标批量计算。

```python
class DynamicFinancialAdapter:
    def __init__(self, storage, param_service, source='akshare'):
        self.storage = storage
        self.param_service = param_service
        self.source = source
    
    def fetch_indicators(self, indicators, symbol, period):
        """
        传入指标定义列表，返回 DataFrame，每列为指标的标准字段。
        """
        # 1. 收集所有需要的 API 调用（去重）
        api_calls = self._resolve_api_calls(indicators, symbol, period)
        
        # 2. 调用每个 API，缓存结果
        api_results = {}
        for api_id, params in api_calls.items():
            api_def = self.storage.get_api_def(api_id)
            kwargs = self._build_kwargs(api_def, symbol, period)
            api_results[api_id] = self._call_api(api_def, kwargs)
        
        # 3. 构建 row 上下文
        row = {}
        for api_id, df in api_results.items():
            if df is not None and not df.empty:
                for col in df.columns:
                    row[col] = df.iloc[0][col]
        
        # 4. 逐个指标计算
        record = {'symbol': symbol, 'end_date': period}
        for ind in indicators:
            value = IndicatorEngine.compute(ind.formula, row)
            record[ind.standard_field] = value
        
        return pd.DataFrame([record])
```

### 4.2 指标计算引擎 (`IndicatorEngine`)

```python
import math

class IndicatorEngine:
    ALLOWED_NAMES = {
        'row': None,       # 运行时传入
        'abs': abs,
        'round': round,
        'max': max,
        'min': min,
        'float': float,
        'int': int,
        'str': str,
        'bool': bool,
        'len': len,
        'math': math,
    }
    
    @classmethod
    def compute(cls, formula: str, row: dict):
        if not formula:
            return None
        allowed = dict(cls.ALLOWED_NAMES)
        allowed['row'] = row
        try:
            return eval(formula, {"__builtins__": {}}, allowed)
        except Exception as e:
            logger.error(f"指标计算公式执行错误: {formula}, 错误: {e}")
            return None
```

### 4.3 公式解析与依赖管理 (`FormulaDependencyParser`)

在保存指标时，系统自动解析公式文本，提取依赖的 `function_name` 和 `column_name`。

```python
class FormulaDependencyParser:
    # 依赖引用语法：api('function_name').col('column_name')
    PATTERN = r"api\('(\w+)'\)\.col\('(\w+)'\)"
    
    @classmethod
    def parse(cls, formula: str) -> List[dict]:
        import re
        deps = []
        for match in re.finditer(cls.PATTERN, formula):
            func_name = match.group(1)
            col_name = match.group(2)
            deps.append({'function_name': func_name, 'column_name': col_name})
        return deps
```

保存指标时：
1. 调用 `FormulaDependencyParser.parse()` 得到依赖列表。
2. 根据 `function_name` 查找 `api_def` 表中对应的 `api_id`。
3. 删除旧依赖，插入新依赖到 `indicator_api_dep`。
4. 若找不到对应 API，发出警告。

## 5. 后端 API 设计

路由：`/api/v1/financial`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/config/apis` | 列出所有 API 定义 |
| POST | `/config/apis` | 新增/编辑 API 定义 |
| DELETE | `/config/apis/{id}` | 删除 API 定义（检查依赖） |
| POST | `/config/apis/probe` | 探测 API 输出列 |
| GET | `/config/indicators` | 列出所有指标（可按 report_group 筛选） |
| POST | `/config/indicators` | 新增/编辑指标（自动解析依赖） |
| DELETE | `/config/indicators/{id}` | 删除指标 |
| GET | `/config/indicators/{id}/deps` | 查看指标依赖的 API 列表 |
| GET | `/config/deps/affected/{api_id}` | 查看某 API 被哪些指标依赖 |
| POST | `/fetch` | 采集财务数据（传入指标列表或 report_group） |

## 6. 前端配置界面设计

### 6.1 页面 (`FinancialConfig.vue`)

使用 **Tab 布局**：

#### Tab 1：指标管理
- 左侧树形按 `report_group` 分组显示指标。
- 右侧编辑区：
  - 标准字段、中文名称、单位等基础信息。
  - **公式编辑器**（Monaco Editor），提供变量 `row` 及 API 列名自动补全。
  - 下方显示“当前依赖的 API 列”列表（实时解析预览）。
- 新增/删除指标按钮。

#### Tab 2：API 管理
- API 列表，显示函数名、数据源、输出列。
- 新增 API 对话框：输入函数名，调用探针获取输出列，自动填充。
- 删除 API 时，弹窗提示受影响的指标列表。

#### Tab 3：依赖分析
- 依赖关系图（可选，ECharts 关系图）。
- 表格视图：选择 API，列出引用它的所有指标；选择指标，列出它依赖的所有 API。

## 7. 初始化与预置数据

### 7.1 初始化脚本

系统启动时检查 `api_def` 表是否为空，若为空则执行：

1. 从预置 JSON 文件 `config/financial_api_presets.json` 读取 AKShare 财务 API 列表，插入 `api_def`。
2. 插入预设指标定义到 `indicator_def`。
3. 运行解析器，自动生成初始依赖记录。

### 7.2 预设指标示例

| standard_field | chinese_name | report_group | formula |
|---------------|--------------|--------------|---------|
| revenue | 营业收入 | income | `row['OPERATE_INCOME']` |
| net_profit | 净利润 | income | `row['NETPROFIT']` |
| roe | 净资产收益率 | indicator | `float(row['roe'])/100` |
| eps | 每股收益 | indicator | `row['eps']` |
| total_assets | 总资产 | balance | `row['TOTAL_ASSETS']` |

## 8. 主控模块重构方案

采用**插件模式**，`main.py` 仅负责创建 FastAPI 实例和启动流程。每个子系统通过 `SubsystemPlugin` 注册。

### 8.1 目录结构
```
backend/app/
├── main.py
├── core/plugins/
│   ├── __init__.py
│   ├── base.py
│   ├── param_plugin.py
│   ├── market_plugin.py
│   └── financial_plugin.py
```

### 8.2 `financial_plugin.py` 关键逻辑

```python
class FinancialPlugin(SubsystemPlugin):
    def init_app(self, app, infra_config, param_service):
        database_url = infra_config['database']['url']
        storage = FinancialStorage(database_url)
        app.state.financial_storage = storage
        
        # 初始化动态适配器（不再需要固定报表）
        adapter = DynamicFinancialAdapter(storage, param_service)
        app.state.financial_adapter = adapter
        
        # 启动时初始化预置数据
        if not storage.has_api_defs():
            self._seed_presets(storage)
    
    def register_routers(self, app):
        from app.api.v1 import financial, financial_config
        app.include_router(financial.router, prefix="/api/v1")
        app.include_router(financial_config.router, prefix="/api/v1")
```
